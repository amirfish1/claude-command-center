## Design (decided)
- `ccc_server/byok.py` (stdlib-only, `_core` proxy). All public names prefixed
  `byok_`/`BYOK_` on purpose — `_adopt_ccc_module` flat-merges every top-level
  name into server.py's globals, and this repo has been bitten by exactly this
  collision before (see W2-1's own note above re: `_iso`/`_lock`/`_wt_run`).
- Storage: macOS Keychain primary (`security` CLI, one generic-password item
  per profile+provider), stdlib-only encrypted-file fallback for non-Darwin
  (HMAC-SHA256 counter-mode stream cipher, PBKDF2 key derivation, machine-
  bound secret seed). Plaintext index (`byok/index.json`) holds only profile
  names + provider lists, never key material.
- No "virtual engine" needed: OpenCode already accepts native
  `<provider>/<vendor>/<model>` ids (e.g. `openrouter/anthropic/claude-sonnet-5`).
  BYOK just recognizes the `openrouter/`/`tokenrouter/` prefix and injects the
  right provider API key env var at spawn time — satisfies the "virtual
  engine" requirement from the brief without new dispatch code.
- Spawn wiring: `byok_spawn_env(engine, model, key_profile)` computed once in
  the `/api/sessions/spawn` handler, passed as `env=` into
  `spawn_session_opencode` (only engine wired so far — see Scope below).
  Successful BYOK spawns get logged via `byok_record_usage` into a JSONL
  ledger (`byok/usage.jsonl`), summarized by `/api/byok/usage?days=N`.
- Model catalog: `BYOK_MODEL_CATALOG` (9 indicative rows w/ per-1M-token cost)
  folded into `_build_engine_model_catalog()`'s opencode bucket so
  `/api/engines/models` and `ccc models` show BYOK-backed models + cost.
- New routes: GET /api/byok/profiles, GET /api/byok/usage,
  POST /api/byok/keys, POST /api/byok/keys/delete.
- Settings UI: new rows in Settings > Engines tab — add-key form
  (profile/provider/key), profile list with per-profile delete, 30-day spend
  summary. Wired via `refreshByokSettings()` called from `openSettingsModal()`.

## Scope decisions (deliberate, to stay out of W2-1's way + match brief's
## "keep changes in engines/settings/spawn paths" instruction)
- Only `opencode` is wired to receive BYOK env at spawn time today. `droid`'s
  spawn is a pre-existing stub (`spawn_session_droid` always returns
  `droid_unavailable`) — nothing to wire until that stub is implemented.
  `aider`'s spawn (`spawn_session_aider`) is fully implemented but is
  pre-existing dead code, never called from server.py's dispatch chain — not
  BYOK's job to fix that gap. `kilo`/`hermes`/`pi` are not present as spawnable
  engines in this build at all yet. `BYOK_DIRECT_ENV_ENGINES` already lists
  all of them so wiring the rest is a one-line addition per engine once their
  spawn paths exist/are fixed — documented as a known follow-up.
- `key_profile` in the spawn payload is honored (falls back to `"default"`
  when a virtual openrouter/tokenrouter model is used with no explicit
  profile).
