## Scope
- `scripts/release_notes.py` — deterministic rule-based generator: git
  range/`--since` in, groups commits into capabilities (new / improved /
  fixed), collapses chore/test/docs/ci/internal-scope-fix commits into an
  "Under the hood" `<details>` block, emits Markdown + styled HTML.
  Optional `--llm` prose-polish pass through local `claude -p`
  (`--disallowedTools`-bounded, degrades to deterministic text on any
  failure) — not run against the shipped output tonight (time budget).
- `tests/test_release_notes.py` — 17 tests: conventional-commit parsing,
  classification, fixture git-log parsing, grouping, markdown/HTML
  rendering, LLM-fallback, one end-to-end throwaway-repo CLI test.
- `docs/release-notes/STYLE.md` — 8 value-first rules for future
  sessions/humans writing release notes.
- `docs/release-notes/2026-09-03.{md,html}` — generated from the real
  last-7-days CCC commit history (`--since "7 days ago"`, 401 commits).

## Decisions
- Existing `scripts/release.py` rolls `changelog.d/` snippets into
  `CHANGELOG.md` (technical ledger). This is a distinct tool answering a
  different question ("what can the user do now") from real commits, not
  from changelog.d snippets — those don't exist for every commit.
- Group key is (bucket, scope) from the conventional-commit prefix; each
  commit renders its own What/Why line under the shared scope heading
  rather than merging unrelated commits into one run-on sentence.
- "Why it matters" is keyword-templated (queue/restart/token/etc.) with a
  bucket-level default fallback — deterministic and honest, not always
  sharp. That's what `--llm` is for later.
