# Lane W6-1 — CCC's GitHub GraphQL quota burn

Status: attribution complete (2026-09-03). Headline: **the burn is NOT CCC's,
and it is not on this machine at all.** CCC's own measured contribution is
small; it is still fixed below, plus the quota observability the lane asked for.

## Method

All costs read from the **authoritative in-band** block (never `gh api rate_limit`,
see runbook OPS-929 / W4-4):

```bash
gh api graphql -f query='{rateLimit{used remaining resetAt}}'
```

Three instruments, logs under `~/Library/Logs/ccc-w6-1/`:

1. `quota-baseline.log` — `used` every 30 s.
2. `exec-gh.log` / `gh-parents.log` — tight `ps -A` loop (~30 samples/s),
   deduped **by the gh process's own pid**, so it counts *invocations*, not
   samples, and resolves each one's parent command.
3. `net-github.log` / `quiet-net.log` — `lsof -nP -iTCP@140.82.116.6`
   (api.github.com) in the same loop: who on this box is actually talking
   to the API.

Per-call cost is measured as **gross minus a drift control of equal wall time**
(the background burn is ~1 pt/s, so an uncontrolled before/after read
overstates every call by seconds-worth of someone else's traffic).

### Two measurements that overturn the prior conclusions

**(a) REST conditional calls cost ZERO GraphQL points.** 10x WatchTower-style
`gh api -i -H "If-None-Match: ..." repos/amirfish1/claude-command-center/issues?...`
moved `used` by 6 over 7 s; an idle control of the same 7 s moved `used` by 6.
Net cost 0. WatchTower's 155 calls/234 s are not in the GraphQL bucket at all.

**(b) `rateLimit`-only queries are free.** 60 back-to-back `{rateLimit{used}}`
queries moved `used` by 76; a 60 s idle control moved it by 83. Net <= 0. Safe
to poll (confirms the runbook claim independently).

### The decisive experiment

93 s window, `lsof -nP -iTCP@140.82.116.6` polled continuously throughout:

```
quiet-window delta = 122 pts over 93 s   => 4,723 pts/hr
local processes connected to api.github.com during the window: 0
```

**122 GraphQL points were spent while nothing on this machine held a
connection to the GitHub API.** The consumer is off-box, on the same GitHub
user ID (GraphQL points are aggregated per user across user-to-server tokens,
which is why the daemon's error reads `for user ID ...`).

Ruled out from here: no scheduled/`cron` workflows in this repo, no
in-progress Actions runs, `infra/telemetry-worker/` contains no GraphQL /
`api.github.com` / `GITHUB_TOKEN` reference at all. `gh api /user/installations`
is 403 for this token, so the authorized-app list cannot be enumerated locally.
Remaining candidates (need a human or another host to check): a remote
agent host (`amirfish1/hermes-vm-ops`), a cloud Claude Code session, or a
GitHub App/OAuth integration authorized on the account. Filed as an OPS ticket.

## Fixes shipped (CCC side)

Even at ~470 pts/hr, CCC was above the lane's 500 pts/hr bar for a *fleet* of
repos and had three real defects:

1. **`gh pr list ... statusCheckRollup` is the most expensive call CCC makes**
   (2.9 pts, vs 1.3 for a 100-issue list) and it lived behind a **30 s,
   memory-only, no-single-flight** cache in *two* places
   (`morning_launch._open_prs_cached`, `fleet._fleet_prs`). Two dashboard tabs
   open = two independent fetches. => shared TTL cache (default 300 s, env
   `CCC_GH_PR_TTL_S`) + single-flight per repo.
2. **`_fetch_one_repo_issues` had a TTL but no single-flight**, and
   `fetch_cross_repo_issues()` fans it out over every known repo in a thread
   pool — N concurrent dashboard requests on a cold/stale cache = N x repos
   fetches. => single-flight per repo.
3. **`--limit` oversized for what the UI renders.** `_fetch_issue_states` asked
   for `--limit 500` (up to 5 pages = 5 pts on a big repo like BYM-Finie);
   `--limit` is the cost lever (1 pt / 100 nodes). => env-tunable, defaults
   sized to the UI (`CCC_GH_ISSUE_LIMIT`).

Plus the observability the lane asked for:

4. `GET /api/github/quota` — in-band `rateLimit` (used/remaining/limit/resetAt),
   cached so the endpoint itself cannot become the burn.
5. `ccc doctor` prints a GraphQL quota line from the same source.
