# Lane W9-1 - ccc doctor stray dashboard instances

## Root Cause

The duplicate-repo guard already records live dashboard instances in
`~/.claude/command-center/registry.json` and refuses a second responding
instance for the same git common-dir. Doctor did not expose that state or the
actual `python server.py` listener ownership, so a forgotten A/B test process
could wedge launchd restarts without showing up in `ccc doctor`.

## Changes

- Added `build_doctor_instances()` and `GET /api/doctor/instances`.
- Included the same payload under `server_instances` in `GET /api/engines/doctor`.
- `ccc doctor` now prints PID, port, start time, and launchd/manual ownership.
- WARNs when more than one repo-local `server.py` exists or when a listener is
  not the launchd-owned process.
- WARN output includes the exact `kill ... && launchctl kickstart -k ...` fix.

## Verification

- `python3 -m py_compile server.py ccc`
