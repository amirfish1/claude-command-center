The problem

You ship a product with real users. You are the support desk, the on-call engineer and the product owner at once.

What it does, and where it stops

Five claims. Each with its limit.

CCC puts coding agents on call for your product. It is a preview. It is off until you turn it on.

01

Bugs come in by themselves.

Reports arrive from GitHub issues, a support mailbox, Sentry, PostHog exceptions, a URL uptime check, any command you already run (a test suite, a health script) and ccc oncall report. Each becomes one ticket in a WatchTower queue, deduplicated, and a worker agent picks it up.

The limit

Mail from someone not on your customer list waits for your go-ahead before an agent works on it. If Dana were not on your list, you would get this first:

New report from dana@example.com (#5)
Checkout button does nothing on Safari

Reply go to have an agent work on it, or no to drop it.
02

You hear when an agent stops or needs you.

One numbered message when an agent asks a question it cannot decide, an agent session dies mid-task, a queue stops moving, or a bug is fixed. The fixed notice is optional. It works with no browser open.

The limit

CCC must be running on a machine that stays on: your Mac, a Linux box or a small VM. Nothing is hosted for you.

03

Small reversible decisions do not reach you.

One switch. An agent that hits a minor, reversible choice states its recommendation and how to undo it, and carries on. Every such decision is listed with its undo.

The limit

Money, messages to customers, public posts and anything that cannot be undone always come to you.

04

Answer from the message.

Reply to the email, Telegram message, iMessage, SMS or WhatsApp message in plain words. The reply becomes the agent's answer and the agent resumes. The same thread also takes status, pause and resume.

The limit

WhatsApp and SMS need your own Twilio number. iMessage needs a Mac. WhatsApp only delivers free text within 24 hours of your last message to the number.

05

Agents can ask your customer.

An agent, or you, asks the person who reported the bug a question, or tells them it is fixed, on the channel they wrote in on. Their reply goes back onto the ticket and the agent resumes.

The limit

Agents never message a customer without your approval unless you turn that off. You see the wording first:

An agent wants to ask Dana (dana@example.com) about SHOP-12 (#6):

Which Safari version are you on, and does it happen in a private window?

Reply yes to send, no to drop, or reply with your own wording.

Setup

Three commands. Off until you run them.

CCC On-call is a preview. It is off until you turn it on. CCC must be running on a machine that stays on: your Mac, a Linux box or a small VM. Nothing is hosted for you.

# turn it on

# 1. turns the preview on, sends a test message
ccc oncall setup

# 2. where bugs come from
ccc oncall source add github

# 3. what is on, what is waiting for you
ccc oncall status

No CCC yet? Install it first.

# or in Settings

  • Settings > Advanced > Preview featuresTurns the preview on.
  • Settings > On-callDoes the setup: the same questions as ccc oncall setup.
  • What you need firstWhatsApp and SMS need your own Twilio number. iMessage needs a Mac. Email needs an address and an app password.

# day to day

# what is on, what is waiting for you
ccc oncall status
ccc oncall on | off

ccc oncall channel add email|telegram|ntfy|imessage|sms|whatsapp|command
ccc oncall source add github|sentry|posthog|http|command

# someone whose reports go straight to an agent
ccc oncall customer add ADDRESS

ccc oncall report "Checkout button does nothing on Safari"

# ask the reporter, or tell them it is fixed
ccc oncall ask REF "Which browser are you on?"
ccc oncall tell REF "This is fixed. Reload the page."
When you want detail

Open the session view.

Every agent, what it is doing, its transcript. You do not need it open for On-call to work. It is there when you want to look.

  • Works with the agents you already runCCC works across nine engines. Claude Code is first-class; Codex, Cursor, Antigravity, Kilo Code, Kimi Code, OpenCode, Grok, and Devin spawn and ingest with documented gaps.
  • Attaches to sessions you already haveCCC reads each engine's on-disk state as truth, so a session you started by hand in a terminal appears too. It does not own your sessions. Close the browser tab and they keep running.
  • Answer and steer in placeA session that ends on a real question is flagged. Type into any session from the browser. Dormant ones resume to receive it.
  • Queues and workersWatchTower is installed by default as CCC's queue engine. Tickets go through claim, fix, verify and close, and you can see which worker holds which ticket.
  • Past the usage limitA Claude session that hits its usage limit can keep going on a free model, then switch back when the limit resets. You choose when in Settings.
  • Runs on your machineSource-available under FSL-1.1-MIT. A stdlib-only Python server and a no-build browser UI. On-call sends the messages you configure, on the channels you set up. Anonymous telemetry is a public contract with no transcripts.

Get it

Start free.

macOS, Linux, or Windows with Python 3.9+. Already use Claude Code or Codex? Your sessions are in the session view when it opens. On-call is a preview and stays off until you turn it on.

# one-line install

# macOS / Linux: downloads, installs, opens CCC in your browser
curl -fsSL https://raw.githubusercontent.com/amirfish1/claude-command-center/main/scripts/install.sh | CCC_FROM=landing bash

# Windows PowerShell
irm https://raw.githubusercontent.com/amirfish1/claude-command-center/main/scripts/install.ps1 | iex

# macOS / Linux: launch later
ccc start                           # then open http://localhost:8090

# Windows PowerShell: launch later
.\run.ps1

Asks before adding its hooks to ~/.claude/settings.json so every Claude Code session writes the sidecar state CCC reads. Idempotent.

# Homebrew or Mac app

# drag-and-drop install (recommended if you avoid the terminal)
Download CCC.dmg ↓

# or via Homebrew
brew install amirfish1/tap/ccc

DMG is notarized and signed by Apple. Drag, drop, double-click. Homebrew installs the ccc command and can run CCC as a background service.

# the ccc CLI: your whole fleet from the terminal

# installed with CCC; talks to the running server
ccc sessions                        # live census: state, age, engine, repo
ccc models                          # every engine's models, efforts, cost
ccc spawn "fix the flaky test" --engine claude --model opus-5-5
ccc send queue-drain "also update the changelog"
ccc ask queue-drain "what's your status?"   # blocks for the reply

Address sessions by id or by name fragment. send is fire-and-forget (with --steer to interrupt a turn), ask waits for the reply. No browser, no hand-rolled curl.
