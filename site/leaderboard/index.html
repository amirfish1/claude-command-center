How the test works

Small jobs. Checks you can trust.

Each model gets the same five jobs in scratch folders, with file tools and a fixed time budget. CCC checks the final files to decide whether a task passed.

  1. Fix a typo in a file
  2. Make a failing test pass
  3. Add a new function
  4. Read one file, write another
  5. Read two files, combine, write

Score = 80% tasks passed + 20% speed. A reply time of 1.5 seconds or less earns full speed credit; 20 seconds or more earns none. Between those times, the credit falls evenly. The median reply is the middle value of the tasks' measured median API reply times, not the time to finish a task. Unmeasured replies are left out.

These are local benchmark snapshots, not a broad study. A row keeps the latest saved result for that model. Providers, free limits, and response times can change. A Top tool-ready badge marks the highest-ranked model with file tools and at least one task passed. It does not confirm that the provider is available now.

Run your own benchmark

Pick a model with your own results.

CCC is a local dashboard for your coding agents. Its setup tour helps you connect a free model provider. You choose when to run the test.

curl -fsSL https://raw.githubusercontent.com/amirfish1/claude-command-center/main/scripts/install.sh | bash
  1. Install CCC. Copy the line into your terminal. A guided setup tour opens in your browser.
  2. Choose a free provider. Some need a free key. Check the provider's limits and privacy terms first.
  3. Open the local leaderboard. In your CCC browser tab, replace the part of the address after the port with /free-models. Choose Run the race. It can take several minutes.

Some keyless providers log prompts for training. CCC asks for consent before enabling them. A benchmark sends its own small test tasks, not your project code. Publishing scores is always a separate, manual step.
